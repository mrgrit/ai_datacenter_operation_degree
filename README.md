# AI데이터센터운영 디그리 (AI Data Center Operations Degree)

> **"한 채의 AI데이터센터를 입학에서 졸업까지 직접 운영한다."**
>
> 학생은 1학기에 가상 기업 **kt66**의 미니 AI데이터센터에 '신입 운영자'로 입사하여,
> 건물과 워크로드를 이해하고(1학기) → 시설과 서비스를 운영하고(2학기) →
> 운영을 자동화하고 지키며(3학기) → 마지막 학기에 통합 실전 프로젝트로
> 그 데이터센터 전체를 책임지고 졸업한다.

---

## 1. 왜 이 디그리인가

AI 시대의 컴퓨팅은 서버 한 대가 아니라 **건물 전체가 하나의 컴퓨터**(Warehouse-Scale
Computer)로 동작한다. 국내외에서 AI데이터센터 건설이 폭증하고 있으나, 이를 **운영**할
인력 — 전력·냉각을 아는 시설 운영자이면서, LLM 서비스를 굴릴 줄 알고, AI 에이전트로
운영을 자동화하며, 보안관제까지 겸하는 사람 — 은 절대적으로 부족하다.

이 디그리는 그 간극을 겨냥한다. 특징은 세 가지다.

1. **하나의 세계관.** 모든 실습이 같은 가상 데이터센터(kt66) 위에서 이루어진다.
   1학기에 게임으로 지어 본 시설을, 2학기에 관제하고, 3학기에 에이전트에게 맡기고
   공격으로부터 지키며, 4학기에 통째로 운영한다. 과목이 바뀌어도 무대는 이어진다.
2. **AI로 일하는 법 자체가 교육 방식이다.** LLM 구축 과목부터 학생은 코드를 치는 대신
   프롬프트를 쓰고 결과를 검증한다(하네스와 루프). 이 방식은 도구가 아니라
   졸업 후의 업무 방식이다.
3. **채점되는 실전.** 시나리오 콘솔이 장애·공격을 발사하고 탐지 SLA·조치 SLA·금지행위를
   자동 채점한다. 공방전(Red vs Blue)은 리더보드로 겨룬다. 평가가 곧 훈련이다.

## 2. 양성 인재상과 진출 직무

| 인재상 | 진출 직무 |
|---|---|
| 시설(전력·냉각)과 IT(서버·네트워크·AI 워크로드)를 **한 화면에서** 읽는 운영자 | 데이터센터/IDC 운영·관제(NOC) |
| 사내 LLM 서비스를 지표로 진단하고 버전·평가·배포를 관리하는 운영자 | LLMOps·AI 서비스 운영 |
| 반복 운영 업무를 AI 에이전트 조직으로 설계·자동화하는 엔지니어 | AI 운영 자동화(Agent Ops) |
| 시설 경보와 보안 경보를 SIEM 한곳에서 관제하고 침해에 대응하는 분석가 | 보안관제(SOC)·침해대응 |

## 4. 스토리라인 — 학기가 이어지는 이유

- **1학기.** "건물이 컴퓨터다." WSC 이론으로 전력·냉각·서버·네트워크·TCO를 배우고,
  타이쿤 게임으로 kW와 PUE와 위약금을 몸으로 겪는다. 동시에 그 건물이 굴리는 워크로드
  (LLM)를 프롬프트 루프로 밑바닥부터 만들어 본다. **무엇을 운영하는지 아는 학기.**
- **2학기.** 이해한 것을 돌린다. NOC 콘솔에서 층별 설비를 관제하며 강사(시나리오 콘솔)가
  발사하는 고장 48종에 SLA 안에 대응하고, 모델 운영 콘솔에서 살아 있는 트래픽과 지표를
  읽으며 LLM 서비스를 버전·평가·배포한다. **운영이 판단의 연속임을 배우는 학기.**
- **3학기.** 사람이 다 할 수 없음을 인정한다. 반복 업무를 스킬·하네스·루프·그래프로
  에이전트 조직에 맡기고(자율성 L1→L3), 동시에 그 데이터센터를 노리는 공격을 SIEM으로
  탐지·대응하는 보안관제를 익혀 공방전으로 겨룬다. NOC의 시설 경보가 이미 SIEM으로
  흘러들고 있으므로, **시설 관제와 보안관제가 한 화면에서 만난다.**
- **4학기.** 전부 합친다. 팀 단위로 kt66 데이터센터를 인수하여 수 주간 무중단 운영한다.
  시나리오 콘솔은 시설 장애를, tw2는 공격을 동시에 발사한다. 에이전트 조직을 어디까지
  믿고 어디에 사람 게이트를 둘지는 팀의 설계다. 최종 산출물은 운영 보고서와 리더보드다.
