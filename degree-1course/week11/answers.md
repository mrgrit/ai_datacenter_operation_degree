# 11주차 실습 정답·해설

> 신설→렌더→삭제 사이클을 **실제 콘솔(:8050) API로 라이브 검증**했다
> ([`lab/verify_week11.sh`](lab/verify_week11.sh), PASS). 조직은 원래 9명으로 복원.

## 파트 A — 신설 (확인 포인트)
- 근무자는 **반드시 팀에 속해야** 한다. 팀 없이 만들면 거부:
  `조직 정합성 오류 · 근무자 …가 어느 팀에도 속하지 않는다`. → 기존 팀(예: soc-team)을 배정.
- 신설 시 페르소나 뼈대가 함께 생성된다(페르소나 없이 roster에만 넣으면 렌더가 실패하므로).

## 파트 B — 자율성 판단 (예시 답)
- **L1(보고 전용)로 시작하는 이유:** 새 근무자는 아직 신뢰가 검증되지 않았다. 관측·보고는
  틀려도 되돌릴 수 있지만, 실행은 되돌리기 어려울 수 있다. "틀렸을 때 무엇이 망가지는가"가
  아직 크므로 **낮게 시작**한다.
- **L2로 올릴 시점:** 일정 기간 L1로 돌려 보고가 정확함이 확인되면, **승인 후 실행(L2)** 로
  승격. 사람이 승인 게이트를 쥔 채 실행만 자동화한다.
- **L3(무인)은:** 위험이 작고 되돌리기 쉬운 반복 일에만. kt66은 대부분 그렇지 않아 신중.
- 채점 포인트: **"낮게 시작해 승격"** 과 **"실패 비용"** 을 근거로 들었는가.

## 파트 C — 렌더
- 렌더해야 페르소나가 각 런타임 형식으로 적용된다. `render ok=true` 확인.
- 페르소나는 **런타임 중립으로 한 번 작성** → 어댑터가 bastion/hermes/claude 형식으로 렌더.

## 파트 D — 되돌리기
- 저장할 때마다 **백업**이 남는다(⑥ 적용 탭). 잘못되면 복원.
- 삭제 시 페르소나 파일은 기본 유지(다시 넣을 수 있게). 실습 정리는 근무자를 삭제해
  조직을 원래 9명으로 복원.

### 검증 출력 (라이브)
```
신설: 9 → 10명 · 자율성=L1
렌더 ok=True
삭제: → 9명 (원복) · 잔재 0
검증 결과: PASS
```

## 왜 이렇게 배우나
- 자동화는 조직을 **바꾸는** 일이지만, 핵심은 **되돌릴 수 있게** 바꾸는 것이다(9주차 롤백과 같은 정신).
- 팀 필수·백업·페르소나 유지 — 전부 "책임의 공백"과 "복원 불가"를 막는 장치다.
- 자율성은 낮게 시작해 신뢰가 쌓이면 올린다.

```bash
API_KEY=<에이전트 운영 키> bash degree-1course/week11/lab/verify_week11.sh
# → 신설·L1·렌더·삭제·정리 → PASS (조직 원복)
```
