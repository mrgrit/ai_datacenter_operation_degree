# 11주차 실습 — 근무자 신설·렌더·되돌리기

> **목표.** 새 근무자 한 명을 만들어 자율성을 배정하고, 페르소나를 렌더해 적용하고,
> 되돌리기(삭제·복원)까지 한 사이클을 돈다. 조직을 바꾸되 **되돌릴 수 있게** 바꾼다.
>
> **소요.** 90분 · **준비물.** 교내망(:8050), 에이전트 운영 **API 키**(신설·렌더·삭제에 필요).

---

## 파트 A. 근무자 신설 (콘솔 ④단계, 또는 API)
> **규칙: 근무자는 반드시 팀에 속해야 한다.** 팀 없이 만들면 "어느 팀에도 속하지 않는다"고 거부된다.

### 콘솔로
1. ④단계에서 **+ 근무자 추가**.
2. 값을 정한다: id(예: `night-triage-<학번>`)·이름·층·존·**팀(기존 팀 선택)**·런타임·모델.
3. **자율성 = L1**(보고 전용)로 시작한다. 이유는 파트 B에서 설명.
4. 추가 → 페르소나 뼈대가 함께 생성된다.

### API로 (참고)
```bash
B=http://192.168.12.100:8050
curl -s -X POST "$B/api/worker?key=$API_KEY" -H 'content-type: application/json' \
  -d '{"id":"night-triage-001","name":"야간 트리아지","floor":"4F","zone":"mgmt",
       "team":"soc-team","runtime":"bastion","model":"local-small","autonomy":"L1"}'
```

## 파트 B. 자율성 판단 (제출물 1)
> **"방금 만든 근무자에게 왜 L1(보고 전용)을 줬는가? 언제 L2(승인 후 실행)로 올릴 수
> 있나?"** — "틀렸을 때 무엇이 망가지는가"와 "낮게 시작해 승격"으로 설명하라.

## 파트 C. 렌더·적용
페르소나를 런타임 형식으로 렌더해야 실제 적용이다.
```bash
curl -s -X POST "$B/api/render?key=$API_KEY&worker=night-triage-001"   # ok:true 확인
```
(콘솔 ⑥단계의 **전체 렌더**로도 가능.)

## 파트 D. 되돌리기 (조직 원복)
1. ⑥단계에서 **백업**이 쌓였는지 확인한다(저장할 때마다 남는다).
2. 실습이 끝나면 만든 근무자를 삭제해 조직을 원래대로 되돌린다.
```bash
curl -s -X DELETE "$B/api/worker/night-triage-001?key=$API_KEY&keep_persona=false"
```
3. 근무자 수가 원래(9명)로 돌아왔는지 확인한다.
