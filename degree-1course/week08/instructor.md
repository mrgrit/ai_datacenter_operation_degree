> **체험②(AI 서비스 운영)의 시작 — 도구가 모델 운영 콘솔(:8060)로 바뀐다.**

## 이번 주 도구
- 모델 운영 콘솔 `http://192.168.12.100:8060/` (5단계: 요청·지표·요구사항·수정·평가배포)
- 실패 유형 검증 스크립트 `week08/lab/verify_week08.sh`
- **모델 운영 API 키**(`API_KEY`) — 평가(`/api/eval`)·배포(`/api/deploy`)에 필요. 지표·질의(`/api/ask`)는 키 불필요.

## 사전 준비 (수업 전 10분) — ★ 중요: 활성 버전을 v1로
학생이 실패를 재현하려면 **활성 버전이 v1(문제 버전)** 이어야 한다. 기본 상태가 v2면 바꾼다.
1. 현재 활성 확인: `curl -s http://192.168.12.100:8060/api/state | python3 -c "import sys,json;print(json.load(sys.stdin)['active'])"`
2. v1로 배포(활성화):
   ```bash
   curl -s -X POST http://192.168.12.100:8060/api/deploy/v1 -H "x-api-key: $API_KEY"
   ```
3. 검증 스크립트로 대조 확인(활성과 무관하게 버전별 평가):
   ```bash
   API_KEY=<키> bash degree-1course/week08/lab/verify_week08.sh   # v1 2/5 → v2 5/5, PASS
   ```
> **수업 후 원복**: 데모가 끝나면 v2로 되돌려 둔다(`/api/deploy/v2`). 9주차에서 학생이
> 직접 v1→새 버전으로 고치므로, 시작 상태만 v1이면 된다.

## 학생에게 시스템 쓰게 하기 (그대로 불러주기)
1. "브라우저로 **http://192.168.12.100:8060/** 를 열어라. 5단계 탭이 있다."
2. "**2단계(지표)** 에서 ok_rate·p95와 실패 카운트(잘림·근거없음·과잉거부·유출)를 적어라."
3. "**1단계(요청)** 에서 빨간 줄(실패)을 찾고, 어떤 페르소나인지 봐라."
4. "직접 물어봐라 — 네 가지 질의로 각 실패를 재현하고 응답 JSON의 신호를 분류해라([lab.md](lab.md) B-1)."

## 강사 시연 포인트
- **트래픽이 약점을 정한다**: 사내직원 40%→근거없음, 개발자 20%→잘림, 보안팀→과잉거부.
- **평가가 문제를 드러낸다**: v1 2/5. E3=과잉거부("패스워드 정책?" 막힘), E4=근거없음(retrieval off),
  E5=잘림(context 512). `verify_week08.sh` 출력을 그대로 보여 주면 강력하다.
- **한 손잡이의 양끝**: 가드레일을 넓히면(v1) 유출은 막지만 과잉거부가 난다. 좁히기만 하면
  유출이 뚫린다. 정밀 패턴이 답(다음 주).

## 자주 막히는 곳 & 대응
- **실패가 재현 안 된다** → 활성 버전이 v2(수정본)일 것. v1으로 배포했는지 확인(사전 준비).
- **/api/ask가 400** → JSON 본문 `{"prompt":"..."}` 형식 확인.
- **평가가 401** → 평가·배포는 API 키 필요(지표·질의는 불필요).
- **"관리자 비밀번호"가 거부됨** → 정상(유출 방지). 실패가 아니라 통과다.

## 채점·피드백 포인트
- 지표·트래픽 관찰 35 · 실패 재현·분류 45 · 이해(설정↔실패 연결) 20.
- 핵심 확인: 4유형을 **증상(JSON 신호)** 으로 구분하는가, 각 유형의 **원인 설정**을 아는가.
- 흔한 오개념: "거부 = 항상 나쁨" → 유출 방지 거부는 옳다. 과잉거부만 문제.
