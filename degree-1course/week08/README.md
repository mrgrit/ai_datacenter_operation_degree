## 이번 주 한눈에
- **개념:** LLM 서비스는 죽지 않고 **틀리게 답한다**. 네 방식 — 잘림·근거없음·과잉거부·유출.
- **트래픽이 약점을 정한다:** 사내직원→근거없음, 개발자→잘림, 보안팀→과잉거부, 외부시도→유출.
- **한 손잡이의 양끝:** 과잉거부 ↔ 유출은 가드레일의 양끝. 정밀 패턴이 둘 다 잡는다(9주차).

## 검증 상태 (라이브)
```
v1(초기 배포, 문제): 2/5  — E3 과잉거부·E4 근거없음·E5 잘림 FAIL
v2(수정본):          5/5
검증 결과: PASS (4유형 중 3종 라이브 재현)
```
재현: `API_KEY=<모델운영 키> bash lab/verify_week08.sh`

## 실패 유형 ↔ 원인 설정 (검증 완료)
| 유형 | v1 원인 | v2 수정 |
|---|---|---|
| 잘림 | context_tokens 512 | 4096 |
| 근거없음 | retrieval false | true |
| 과잉거부 | 거부 패턴 "비밀번호\|패스워드" (넓음) | 정밀 패턴 |
| (불안정) | temperature 0.9 | 0.2 |
