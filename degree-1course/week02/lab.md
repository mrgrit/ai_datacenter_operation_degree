# 2주차 실습 — 인수한 시설 한 바퀴와 증설 판단

> **목표.** 타이쿤에서 인수한 시설의 용량(랙·냉각·전력)을 직접 읽고, 계약을 받아
> "자리의 벽"과 "제열의 벽"을 만난 뒤, 병목 지점을 찾아 증설을 판단한다. 계산은 게임
> 모형으로 자동 검증한다.
>
> **소요.** 60–90분 · **준비물.** 웹 브라우저, (검증용) Node.js

---

## 파트 A. 타이쿤 — 인수한 시설 한 바퀴

### A-0. 실행
- 플레이(새 게임): **https://mrgrit.github.io/data_center_tycoon/**
- 인수 시점에는 **표준 랙 4대 + CRAC 2대**가 이미 놓인 "돌아가는 시설"을 물려받는다.

### A-1. 미션
1. **시설 파악.** 상태/설비 패널에서 다음을 찾아 적는다: 표준 랙 자리(kW), 제열 능력(kW),
   수전·변압기·UPS·냉동기 용량(kW), 시작 현금.
2. **첫 계약.** 작은 공랭 계약(웹 호스팅 등)을 하나 받는다. **랙 부하(used)** 가 오르는 걸 확인.
3. **자리의 벽.** 랙이 꽉 찰 때까지 계약을 더 받아 본다. 어느 순간 "랙 여유가 N kW
   필요하다"며 **거절**되는 걸 확인한다.
4. **제열의 벽(관찰).** 부하를 계속 올리면 **제열 여유**가 줄고, 모자라면 방 온도가
   오르기 시작한다. 어느 지점에서 온도가 22℃를 벗어나는지 본다.
5. **증설.** 막힌 지점(자리? 냉각? 전력?)을 하나 골라 늘려 보고, 거절되던 계약이
   받아지는지 확인한다.

### A-2. 관찰 기록 (제출물 1)
| 항목 | 값 |
|---|---|
| 표준 랙 자리(kW) / 제열 능력(kW) | |
| 수전 / 변압기 / UPS / 냉동기 (kW) | |
| 계약이 처음 거절된 순간의 사유 | |
| 내가 고른 증설과 그 이유 | |

## 파트 B. 계산 — 그리고 자동 검증

### B-1. 다섯 문제 (손으로 먼저)
1. **인수 시설.** 표준 랙 4대의 총 자리(kW)와 CRAC 2대의 제열 능력(kW)은?
2. **전력 병목.** 수전 200·변압기 250·UPS 150일 때, IT 부하의 실제 상한은 대략 몇 kW이고
   그 상한을 정하는 장비는? (힌트: 경로 상한 = min(수전,변압기)÷1.45, UPS 상한 = UPS÷1.1,
   둘 중 작은 값)
3. **자리의 벽.** 표준 랙 4대(자리 40kW)에 40kW를 올린 뒤 30kW를 더 받으면?
4. **제열의 벽.** 고밀도 랙 4대(자리 100kW) + CRAC 2대(제열 80kW)에 100kW를 올리면 제열
   여유는?
5. **증설 비용.** 수전 +200kW, 냉동기 +250kW, 다음 층(2층) 개설은 각각 얼마?

### B-2. 자동 검증
```bash
cd degree-1course/week02/lab
node verify_week02.mjs
```
기대 출력(핵심):
```
[문제 1] ... 표준 랙 총 용량(kW): 40 / 제열 능력(kW): 80
[문제 2] ... UPS 가 받쳐 줄 IT(kW): 136.36  → 병목 = UPS
[문제 3] ... 40kW 로 표준랙이 꽉 찬다 / 30kW 추가 배치 성공?: false
[문제 5] ... 100kW 배치는 되지만 제열 여유(kW)는 음수: -20
[문제 6] ... 수전 +200kW 40000000 / 다음 층(2층) 180000000
검증 결과: 29/29 통과
```
`29/29 통과`가 나오면 성공. **강사·조교가 이미 실행해 검증을 마쳤다**(아래 참조).

### B-3. 제출물 2 — 한 문장 판단
> **"인수한 시설의 IT 상한이 UPS(150kW) 때문에 약 136kW다. 그런데 아직 랙은 40kW어치뿐이다.
> 지금 당장 UPS를 더 사는 게 맞을까, 아니면 다른 걸 먼저 늘려야 할까? 무엇을 근거로?"**
