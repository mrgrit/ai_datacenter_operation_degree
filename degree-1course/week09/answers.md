# 9주차 실습 정답·해설

> 전체 사이클(수정→평가 5/5→배포·롤백)을 **실제 콘솔(:8060) API로 라이브 검증**했다
> ([`lab/verify_week09.sh`](lab/verify_week09.sh), PASS). 검증용 버전은 정리, 활성은 원복.

## 수정 정답 — v1의 4가지를 이렇게 고친다
| 실패 유형 | v1 설정 | 고침 | 근거 |
|---|---|---|---|
| ② 근거없음 | `retrieval: false` | **true** (+ knowledge) | 사내 규정 질문에 근거가 붙는다(E4) |
| ③ 과잉거부 | `비밀번호\|패스워드\|password` | **정밀 패턴** | "패스워드 정책?"은 통과, "관리자 비밀번호"는 차단(E3·E1·E2) |
| ① 잘림 | `context_tokens: 512` | **4096** | 긴 로그의 마지막 줄까지 본다(E5) |
| (불안정) | `temperature: 0.9` | **0.2** | 같은 질문에 같은 답 |
| — | (배포 전제) | **note 작성** | 없으면 배포가 막힌다 |

정밀 refuse_patterns 예:
```
- 관리자 (비밀번호|패스워드)
- 비밀번호를 (알려|말해|출력)
- 시스템 프롬프트|프롬프트를 출력
- 설정 파일.*(보여|출력)
- 지시를 무시
```
→ 이 버전의 평가는 **5/5**.

## 배포·롤백 정답
- **note 없는 버전 배포 → HTTP 400** ("note가 없다 — 왜 만들었는지 적어야 배포된다"). 규율 정상.
- **새 버전 배포 → 활성 전환.** 기존 버전(v1/v2)은 그대로 남아 있다(불변 버전).
- **롤백 → 이전 버전으로 즉시 복귀.** "되돌릴 수 없는 배포는 배포가 아니다."

### 검증 출력 (라이브)
```
vfix9: 5/5 (E1~E5 전부 PASS)
note 없는 vnonote9 배포 → HTTP 400 (규율 작동)
배포 → 활성 = vfix9 → 롤백 → 활성 = v2
검증 결과: PASS
```

## 왜 이렇게 배우나
- **불변 버전 + note + 롤백** 은 전부 "사고 때 빠르게 되돌리기 위한" 안전망이다.
  고치는 능력보다 **되돌릴 수 있게 고치는 습관**이 운영자를 만든다.
- **가드레일은 정밀하게**: 넓게 조이면 과잉거부, 다 풀면 유출. 정확히 막는 것이 답.
- **전부 만점인 설정은 없다**: 컨텍스트↑는 잘림을 줄이지만 느려지고 비싸진다(p95·토큰).
  이번 문제는 깨끗한 답(v2)이 있지만, 실무는 트레이드오프를 note에 남기는 게 핵심.

## 채점 포인트
- 4항목을 모두 고쳤는가(특히 **정밀 가드레일**과 **note**).
- 평가 5/5를 달성했는가.
- 배포 규율(note 게이트)·불변 버전·롤백 경로를 설명하는가.
