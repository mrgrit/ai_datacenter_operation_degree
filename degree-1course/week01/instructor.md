## 사전 준비 (수업 전 5분)
1. 프로젝터로 타이쿤 URL이 열리는지 확인(교내망/외부망 어디서 여는지 미리 결정).
2. (선택) 강사 노트북에서 검증 스크립트 한 번 돌려 두기:
   ```bash
   cd degree-1course/week01/lab && node verify_week01.mjs   # 16/16 통과 확인
   ```
3. 학생 안내 슬라이드 1장: "오늘 열 것 = 타이쿤 URL 하나. 그게 전부."

## 학생에게 시스템 쓰게 하기 (그대로 불러주기)
1. "브라우저에서 **bit.ly/ai_data_center 말고, 타이쿤 URL**을 연다: `…/?demo=1`."
2. "조작은 넷뿐 — 클릭=설치, 우클릭=철거, 휠=확대, Space=일시정지."
3. "상단 게이지에서 **IT 부하·총 수요·PUE·현금** 네 숫자를 찾아 적어라(계약 받기 전)."
4. "제안 목록에서 작은 계약 하나(웹 호스팅)를 받아라. **IT 부하가 오르는지** 봐라."
5. "며칠 돌린 뒤 온도·PUE를 다시 적어라. 세 숫자가 **함께 움직였는지**가 오늘의 핵심."

## 자주 막히는 곳 & 대응
- **저장이 사라진다** → 타이쿤은 브라우저 `localStorage` 저장. 같은 브라우저/기기에서 이어
  하도록 안내(시크릿 창·기기 변경 시 초기화됨).
- **숫자가 안 뜬다/멈춘 것 같다** → 탭이 백그라운드면 느려질 수 있음. 탭을 앞으로.
- **계산이 검증과 다르다** → 손계산은 근사, 정확값은 `verify` 출력 기준. "왜 다른가"를 토론 소재로.

## 채점·피드백 포인트
- 배점: 관찰 기록 40 · 손계산(검증 대조) 30 · 판단 40? → [lab.md](lab.md) 평가표대로.
- **관찰이 핵심**: 값의 정확도보다 "부하↑ 때 무엇이 함께 움직였나"를 적었는지 본다.
- 흔한 오개념: "PUE는 고정" → 냉각 선택·바깥 기온에 따라 변한다는 걸 4문항으로 짚어 준다.
