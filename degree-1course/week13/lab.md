# 13주차 실습 — 두 무대 동시 운영

> **목표.** 시설 고장을 관제하는 **그 시간에** 사내 LLM 서비스도 계속 돈다. 두 무대를
> 동시에 쥐고, 무엇을 먼저 볼지 우선순위로 판단하며, 그 이유를 기록한다.
>
> **소요.** 90분 · **준비물.** 교내망(:8020 NOC, :8040 콘솔, :8060 모델 운영), 학생 에이전트.

---

## 준비 — 두 무대를 함께 연다
- 브라우저 탭 2개: **NOC(:8020)** + **모델 운영(:8060)**.
- 학생 에이전트 상주(5~6주와 동일):
  ```bash
  python3 kt66_scenario_agent.py --server http://192.168.12.100:8040 --name "홍길동" --cohort A
  ```

## 파트 A. 동시 운영
1. **강사가 시설 고장을 발사**한다(예: 냉각 계열). 동시에 **서비스 트래픽이 계속 흐른다.**
2. 시설을 **트리아지**한다(인지→범위→원인→조치→통보, `--report`/`--submit`).
3. **틈틈이 모델 운영(:8060) 지표를 확인**한다 — ok_rate·실패 카운트가 그사이 망가지지 않았나?
4. 필요하면 직접 질의(`/api/ask`)로 서비스가 정상인지 점검한다.

## 파트 B. 우선순위 로그 (제출물 1)
동시 운영 중 "무엇을 먼저 봤고, 왜"를 시각과 함께 짧게 남긴다.
| 시각(대략) | 무엇을 먼저 | 왜(우선순위) | 그때 미룬 것(대가) |
|---|---|---|---|
| | | | |
| | | | |

예: "냉각 온도가 27℃ 넘어 먼저 대응(②·③). 서비스 지연 약간은 감수(대가)."

## 파트 C. 마무리
- 시설 대응을 `--submit`으로 제출하고, 서비스 지표가 정상 범위로 돌아왔는지 확인한다.

## 검증 상태 (강사/조교 기록)
- 검증 스크립트: [`lab/verify_week13.sh`](lab/verify_week13.sh) (발사에 강사 키 필요)
- **실행 결과: PASS** — 시설 시나리오에 **100/100** 대응(탐지·조치 SLA 준수)하는 **동시에**
  서비스 트래픽이 흐름(요청 수 증가 확인). 한 학생이 두 무대를 동시에 운영하는 것을 재현.
  ```
  서비스 요청 수 46 → 49 (관제 중에도 트래픽이 흐름)
  시설 채점: 100.0/100 · 탐지=True 조치=True
  검증 결과: PASS
  ```
- 재현: `INSTRUCTOR_KEY=<강사키> bash lab/verify_week13.sh`
