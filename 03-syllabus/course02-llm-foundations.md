# 수업계획서 초안 — ② LLM의 이해와 구축 (LLM from Prompt)

| 항목 | 내용 |
|---|---|
| 이수구분 / 학점 | 전공필수 / 3학점 (이론 1 + 실습 2) |
| 이수학기 / 선수과목 | 1학기 / 없음 (코딩 경험 불요 — 강좌 설계 전제) |
| 주교재 | 「프롬프트로 밑바닥부터 만드는 LLM」 (bit.ly/llm_from_prompt) |
| 실습환경 | 교내 GPU 서버(gpt-oss:120b) + hermes 에이전트 + llm_from_prompt 하네스(run_loop.sh / verify.sh) |
| 원서(참고) | Raschka, *Build a Large Language Model (From Scratch)* (한국어판: 길벗) |

## 교과목 개요
학생은 코드를 치지 않는다. 한국어로 요구사항(프롬프트)을 쓰고, 코딩 에이전트가 만든
코드를 실행·검증한다. 이 루프를 챕터마다 돌리며 두 가지를 동시에 배운다 —
**LLM의 내부 구조**(토큰화→어텐션→GPT→사전훈련→미세조정)와 **AI 에이전트에게
정확히 요구하고 꼼꼼히 검증하는 능력**(졸업 후의 업무 방식). 만드는 쪽과 채점하는
쪽이 분리된 하네스(verify.sh), 실패 시 3회 규칙 등 이 과목의 작업 방식 자체가
⑤ 에이전트 과목의 선행 체험이 된다.

## 학습 목표
1. LLM의 본질(다음 단어 예측)과 사전훈련·미세조정 2단계를 설명할 수 있다.
2. 토큰화·임베딩·어텐션·트랜스포머 블록의 역할을 손계산 예시로 설명할 수 있다.
3. 프롬프트에 파일명·라이브러리·출력 형식을 못 박아 에이전트가 재량으로 벗어나지 않게 작성할 수 있다.
4. 생성된 코드를 기대 출력과 대조 검증하고, 실패 시 프롬프트의 모호점을 찾아 보완할 수 있다.
5. GPT-2 공개 가중치를 복원해 분류·지시 미세조정을 수행하고 결과를 평가할 수 있다.

## 주차별 계획

| 주 | 주제 (교재 매핑) | 실습 (프롬프트 루프) |
|---|---|---|
| 1 | 0장 오리엔테이션 — 하네스와 루프, 3회 규칙 | setup.sh 자가진단, 첫 루프(step01: 문자 수 20479) |
| 2 | 1장 LLM 이해 — 다음 단어 예측, 사전훈련/미세조정, 트랜스포머 큰 그림 | 바이그램 손계산 + 파이토치 텐서 첫 스텝 |
| 3 | 부록 A 파이토치 입문 †(보강 필요) | 텐서·자동미분·간단한 훈련 루프 |
| 4 | 2장 텍스트 데이터 I — 토큰화, 어휘 | 정규식 토큰화(4,690 토큰), BPE 비교 |
| 5 | 2장 텍스트 데이터 II — 슬라이딩 윈도, 임베딩 | 데이터 로더·임베딩 스텝 |
| 6 | 3장 어텐션 I — 단순 어텐션, Q·K·V | 어텐션 가중치 손계산 → 코드 검증 |
| 7 | 3장 어텐션 II — 인과 마스크, 멀티헤드 | 멀티헤드 어텐션 스텝 |
| 8 | **중간 평가** — 지필(1~3장) + 실기(미공개 스텝 1개를 제한시간 내 루프로 통과) | |
| 9 | 4장 GPT 구현 I — 블록 조립(LayerNorm·GELU·FFN) | GPT 골격 스텝 |
| 10 | 4장 GPT 구현 II — 파라미터 수 세기, 텍스트 생성 | 1.24억 파라미터 검증, 첫 생성 |
| 11 | 5장 사전훈련 I — 손실·훈련 루프 | 소규모 사전훈련 실행 |
| 12 | 5장 사전훈련 II — 공개 가중치 적재 | GPT-2 가중치 복원, 생성 품질 비교 |
| 13 | 6장 분류 미세조정 — 스팸 판별기 | 분류 헤드·동결·기준선 대비 평가 |
| 14 | 7장 지시 미세조정 †(보강 필요) | 지시-응답 데이터로 미세조정, 응답 평가 |
| 15 | **기말 평가** — 지필(4~7장) + 전체 파이프라인 검증 통과율 결산 | |

† 3주(부록 A)와 14주(7장)는 현재 교재에서 '예정' 상태다. **개설 전 집필 완료가 필수**이며,
이 항목은 [04-improvement-analysis.md](../04-improvement-analysis.md)의 최우선 보강 과제다.

## 평가
실기(스텝 검증 통과율·중간/기말 실기) 50 / 지필 30 / 프롬프트 품질·판단 기록 20.
프롬프트 품질은 "실패 후 무엇을 고쳤는가"의 기록(3회 규칙 로그)으로 채점한다 —
실패는 감점이 아니라 데이터라는 교재 철학을 따른다.

## 운영 메모
- GPU 서버 동시접속: 수강 인원 × 루프 실행 빈도로 gpt-oss:120b 서빙 처리량 사전 검증 필요.
- 원서(한국어판) 병행 읽기를 권장 도서로 안내.
- 여기서 배운 "요구를 정확히 정의하고 결과를 검증하는 능력"이 ④·⑤ 과목의 공용 기초다.
